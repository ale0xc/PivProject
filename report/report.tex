\section{Motivations}

This project aims to estimate geometric transformations between a reference image and a sequence of images using classical and modern computer vision techniques. The project is structured in two parts:

\begin{itemize}
    \item \textit{Part 1 : }Estimation of 2D homography from grayscale images
    \item \textit{Part 2 : } Estimation of rigid 3D transformation (rotation and translation) from RGB-D data
\end{itemize}

These techniques find applications in object tracking, 3D reconstruction, robotic localization, and augmented reality.

\section{Part 1: Planar Object Tracking via Homography}

This section describes the implementation of a 2D planar tracking system that estimates the Homography ($H$) between a reference template and a sequence of video frames.

\subsection{Algorithmic Details}

\subsubsection{Feature Extraction and Matching}

The system utilizes the \textbf{Scale-Invariant Feature Transform (SIFT)} to : 
\begin{itemize}
    \item Detect interest points robust to scale and rotation
    \item Extract 128-dimensional invariant descriptors
    \item Generate a `.mat` file per frame containing keypoints and descriptors
\end{itemize}

\textit{SIFT Parameters :} OpenCV defaults ($\sigma = 1.6$, standard octaves and scales)

Then, feature matching is performed between the template and each frame using the following strategy:

We use Euclidean distance metric combined with \textbf{Lowe's ratio test} to filter ambiguous matches:
```
For each descriptor in the frame:
  - Find the 2 nearest neighbors in the template
  - If distance(NN1) < 0.75 × distance(NN2), accept the match
```
The threshold of 0.75 is chosen based on Lowe's original paper to balance precision and recall.

\subsubsection{Homography Estimation (DLT with Normalization)}
The relationship between planar points in the template ($\mathbf{x}$) and the frame ($\mathbf{x}'$) is modeled by a $3 \times 3$ Homography matrix $H$ such that $\mathbf{x}' \sim H\mathbf{x}$. The \textbf{Direct Linear Transform (DLT)} algorithm is used to solve for $H$ using Singular Value Decomposition (SVD).

\paragraph{Data Normalization} A crucial step implemented is isotropic normalization. Before applying DLT, points are translated so their centroid is at the origin and scaled so the average distance from the origin is $\sqrt{2}$. This improves the numerical stability of the SVD.

\begin{equation}
    T_{norm} = \begin{bmatrix} s & 0 & -s \cdot c_x \\ 0 & s & -s \cdot c_y \\ 0 & 0 & 1 \end{bmatrix}
\end{equation}

\paragraph{Matrix A Construction} For N correspondence points $(x_i, y_i) \rightarrow (u_i, v_i)$, create a $2N \times 9$ matrix:
   $$A_i = \begin{pmatrix} -x_i & -y_i & -1 & 0 & 0 & 0 & x_i u_i & y_i u_i & u_i \\ 0 & 0 & 0 & -x_i & -y_i & -1 & x_i v_i & y_i v_i & v_i \end{pmatrix}$$

\paragraph{SVD and H Extraction} $H = VT^{-1}$, where $V$ comes from complete SVD

\paragraph{Denormalization}
The final Homography is denormalized via: 
\begin{equation}
    H = T_{dst}^{-1} H_{norm} T_{src}
\end{equation}

\subsubsection{Robust Estimation (RANSAC)}
To handle mismatches effectively, a Random Sample Consensus (RANSAC) scheme is implemented with the following parameters:
\begin{itemize}
    \item \textbf{Iterations:} 5000.
    \item \textbf{Sample Size:} 4 points (minimum required for DLT).
    \item \textbf{Inlier Threshold:} 3.0 pixels.
    \item \textbf{Refinement:} After identifying the best model, $H$ is re-computed using \textbf{all} inliers found by the best model to minimize the reprojection error via least squares.
\end{itemize}

\subsection{Experimental Setup and Evaluation}

\paragraph{Dataset} We used the TAAG dataset, which provides a reference template image and a sequence of frames with varying perspectives and occlusions.

\paragraph{Evaluation metrics} We considered the \textit{number of inliers} as an indicator of matching quality and \textit{robustness} as an ability to handle partial occlusions and significant transformations

\paragraph{Execution Pipeline}
For every frame:
\begin{enumerate}
    \item Features are extracted and matched against the pre-computed template features.
    \item RANSAC estimates the best $H$.
    \item The result is stored as a \texttt{.mat} file containing the $3 \times 3$ matrix.
\end{enumerate}

\subsection{Example Results}
The algorithm successfully tracks the template even under perspective distortion. The visualization (conceptually) involves projecting the four corners of the template onto the current frame using $H$.

2.3 Example Results

**Typical result for a frame:**
- **Raw Matches (after ratio test):** ~50-100 correspondences
- **RANSAC Inliers:** ~40-80 (80-85 acceptance rate)
- **Average Reprojection Error (inliers):** < 1.5 pixels

\textbf{Output File:} \texttt{homography\_0001.mat} contains the H matrix ($3 \times 3$) representing the projective transformation

**Observations:**
- Point normalization is crucial for numerical stability
- RANSAC is robust to residual false matches
- Estimated homographies enable template reprojection on each frame with sub-pixel accuracy

\section{Part 2: 3D Rigid Body Motion Estimation}

This section details the estimation of the camera's 3D trajectory (Odometry) by calculating the Rigid Body Transformation ($R, T$) between consecutive frames.

\subsection{Algorithmic Details}

\subsubsection{Feature Extraction and Matching}

\begin{itemize}
    \item Use SIFT on RGB images to identify 2D-2D correspondences
    \item Apply same Lowe's ratio test (threshold = 0.75)
    \item Recover SIFT descriptors robust to lighting changes
\end{itemize}

\subsubsection{3D Point Generation}
Unlike Part 1, this module utilizes RGB-D data. 2D keypoints $(u, v)$ are back-projected into 3D space $(X, Y, Z)$ using the corresponding depth map and the Pinhole Camera Model intrinsics matrix $K$:

\begin{equation}
    Z = \text{depth}(v, u)
\end{equation}
\begin{equation}
    X = \frac{(u - c_x) \cdot Z}{f_x}, \quad Y = \frac{(v - c_y) \cdot Z}{f_y}
\end{equation}
Points with invalid depth ($Z \le 0$) are discarded.

\subsubsection{Orthogonal Procrustes Analysis}
To find the rotation $R$ and translation $T$ that align two clouds of 3D points ($P_B \approx R \cdot P_A + T$), the Procrustes method is used.
\begin{itemize}
    \item \textbf{Centering:} Centroids of both point clouds are subtracted.
    \item \textbf{SVD:} The cross-covariance matrix $H =  P_B^T × P_A$ is decomposed into $U, \Sigma, V^T$.
    \item \textbf{Rotation:} $R = UV^T$.
    \item \textbf{Reflection Correction:} To ensure a valid rotation (determinant $+1$) rather than a reflection (determinant $-1$), if $\det(R) < 0$, the last row of $V^T$ is negated.
    \item \textbf{Translation:} $T = \bar{P_B} - R \cdot \bar{P_A}$, where $\bar{P_A}$ and $\bar{P_B}$ are the centroids of the original point clouds.
\end{itemize}

\subsubsection{RANSAC for 3D Alignment}
A RANSAC loop wraps the Procrustes method to be robust against depth noise and matching errors:
\begin{itemize}
    \item \textbf{Iterations:} 1000.
    \item \textbf{Sample Size:} 3 points (minimum for rigid alignment).
    \item \textbf{Threshold:} 0.01 (meters), applied to the Euclidean distance between transformed source points and target points.
\end{itemize}

\subsection{Experimental Setup and Evaluation}

\paragraph{Dataset}
\begin{itemize}
    \item 1 RGB template + depth (\texttt{template\_depth.mat})
    \item 12 RGB frames + depth (\texttt{frame\_NNNN.mat})
    \item Resolution: typically $640\times 480$ pixels
    \item Depth format: H\texttimes{}W matrix with values in millimeters
\end{itemize}

\paragraph{Evaluation metrics }
\begin{itemize}
    \item \textbf{Number of Valid 3D Correspondences:} Indicator of matching quality and depth density
    \item \textbf{RANSAC Inliers:} Ratio of robustness in pose estimation
    \item \textbf{Average 3D Error:} For inlier points
\end{itemize}

\paragraph{Execution Pipeline}
The system iterates through pairs of \texttt{frame\_RGB} and \texttt{frame\_Depth}.
\begin{enumerate}
    \item Load RGB template + depth
    \item For each frame:
    \begin{itemize}
        \item Extract and match SIFT features
        \item Back-project matched 2D points to 3D using depth maps
        \item Run RANSAC + Procrustes to estimate $R, T$
        \item Store results in \texttt{.mat} files containing $R$ and $T$
    \end{itemize}
\end{enumerate}

\subsection{Example Results}
The resulting $R$ and $T$ matrices describe the camera's motion. By concatenating these transformations, the global trajectory of the camera can be plotted. The use of RANSAC significantly reduces "jumps" in the trajectory caused by noisy depth values at object boundaries.
3.3 Example Results

**Typical result for a frame:**
- **2D-2D Correspondences:** ~60-150 SIFT matches
- **Valid 3D Correspondences** (depth available): ~50-120
- **RANSAC-Procrustes Inliers:** ~40-100 (70-85 acceptance)
- **Average Error (inliers):** 1-3 cm

\textbf{Output File:} \texttt{transform\_NNNN.mat} contains R ($3 \times 3$ orthogonal rotation matrix) and T ($3 \times 1$ translation vector)

**Validation:**
- Matrix R satisfies $R^T R = I$ (orthogonality)
- det(R) = 1 (pure rotation, no reflection)
- Vector T represents translation in meters (or depth units)

\section{Discussion and Limitations}

\subsection{Comparison of Methods}
\begin{itemize}
    \item \textbf{2D Homography (Part 1):} Efficient for tracking planar objects. However, it fails if the target object is non-planar or if the camera motion induces significant parallax that a planar model cannot represent. The DLT normalization implementation is critical for maintaining accuracy when coordinates are large.
    \item \textbf{3D Procrustes (Part 2):} Provides full 6-DoF pose estimation. It requires depth data, making it dependent on the quality of the depth sensor. The implementation correctly handles coordinate system reflections, which is a common pitfall in SVD-based estimation.
\end{itemize}

\subsection{Identified Limitations}

\paragraph{Part 1}
\begin{itemize}
    \item Limited to planar scenes
    \item Sensitive to lighting changes (though SIFT mitigates this)
    \item Requires sufficient extractable features
\end{itemize}

\paragraph{Part 2}
\begin{itemize}
    \item Critical dependency on depth data quality (noise, holes)
    \item Degraded performance if valid 3D correspondences < 3 (RANSAC MSS)
    \item Sensitivity to calibration of K
\end{itemize}

\subsection{Conclusion}
The implemented pipeline demonstrates a standard computer vision approach: Feature Extraction $\rightarrow$ Matching $\rightarrow$ Robust Model Estimation. The use of SVD for both DLT and Procrustes ensures mathematically rigorous solutions to the minimization problems.
