Abstract—This report documents our implementation of a document 
tracking and rectification system. In Part 1, we estimate 
homographies from RGB images using SIFT features, RANSACbased 
outlier rejection, and the normalized DLT algorithm. In 
Part 2, we extend the system to RGB-D data, using depth 
information to compute 3D point correspondences and estimate 
rigid transformations via Procrustes analysis. 

I. PART 1: HOMOGRAPHY ESTIMATION 
The goal of Part 1 is to estimate homographies that map each 
frame in a video sequence to a reference template image, 
enabling perspective-corrected (rectified) views of a planar 
document. 

A. Feature Detection and Matching 
We use SIFT [1] to detect keypoints and compute descriptors. 
SIFT provides robustness to scale and rotation changes, both 
of which occur frequently during document tracking under 
camera motion. 

Motivation: We chose SIFT over simpler detectors (e.g., 
Harris, FAST) for its scale invariance, since the document occupies 
varying image regions as the camera moves. SIFT also 
handles arbitrary document orientations through its rotation 
invariance. Unlike deep learning approaches, SIFT requires 
no training data and remains interpretable. 

Feature matching is performed using a KD-tree for efficient 
nearest-neighbor search. We apply Lowe’s ratio test to filter 
matches: a match is accepted only if the distance to the nearest 
neighbor is less than 0.75

B. RANSAC for Outlier Rejection 
Given a set of candidate correspondences, we use RANSAC 
to robustly estimate the homography while rejecting outlier 
matches caused by occlusions, texture ambiguities, or moving 
objects. 

To avoid unnecessary RANSAC invocations on extremely 
weak match sets, a minimum of 10 putative matches is 
required before attempting homography estimation. 

Motivation: Even with Lowe’s ratio test, false matches persist 
in low-texture regions and under occlusions. A least-squares 
fit fails with even a few outliers. RANSAC addresses this by 
iteratively searching for the largest inlier set, tolerating the 
noise present in real video data.

D. Tracking Strategy 
Our pipeline processes frames using a combination of direct 
matching and a keyframe-based chaining strategy to handle 
drift and temporary occlusions: 

Motivation: Matching every frame directly against the template 
fails when the document rotates significantly or is 
occluded. Keyframe chaining allows a frame to be tracked via 
an intermediate keyframe when direct template matching fails. 
The conservative keyframe update rule (15 inliers required) 
limits drift accumulation from weak intermediate links. 

1) Direct Matching: Each frame is first matched directly 
against the template. If a strong match is found (at least 
15 inliers), the homography is computed directly, and the 
current frame is designated as the new reliable keyframe. 
Choice of 15 inliers: This threshold was empirically 
tuned to balance reliability and coverage. Fewer inliers 
would accept unreliable keyframes; more inliers would 
miss opportunities to update and cause tracking to fail 
when the template has poor visibility. 
2) Keyframe Chaining: If direct matching fails to meet the 
strict inlier threshold, the frame is matched against the 
most recent reliable keyframe. If this chain produces a 
valid transformation (at least 8 inliers), the homography 
is composed: 

Hframe→template = 
Hkeyframe→template · 
Hframe→keyframe (7) 

Choice of 8 inliers for chaining: A lower threshold 
(8 vs. 15) is acceptable here because we are only 
estimating relative motion between two nearby frames, 
which typically has better visibility than direct template 
matching. The reduced threshold allows tracking to 
continue when visibility is marginal, while 8 inliers still 
provides enough geometric constraint to avoid spurious 
solutions. 
Note that while this allows tracking to continue, the reference 
keyframe is only updated when a frame matches 
the template directly or through a very strong chain (15 
inliers), preventing drift accumulation from weak links. 

3) Backward Pass: To handle frames at the beginning of 
the sequence that may have poor direct visibility of 
the template, we perform a backward pass using the 
same keyframe logic, propagating valid transformations 
in reverse order from the first successfully tracked frame. 
Motivation for backward pass: Early frames may be 
occluded or at extreme viewpoints. The forward pass 
identifies the first trackable frame as an anchor. The 
backward pass then links earlier frames to this anchor. 
This two-pass strategy handles sequences where the first 
frames lack direct template visibility. 
The homography H 
estimated in this pipeline maps points 
from the current frame coordinate system to the template. 
For rectification, this transformation is used to warp the frame 
content back onto the reference template plane. 

Summary of Part 1: The homography estimation pipeline 
combines SIFT-based feature matching, Lowe’s ratio test, 
RANSAC outlier rejection, and normalized DLT to track a 
planar document across video frames. The keyframe-based 
chaining strategy with forward and backward passes handles 
occlusions and viewpoint changes. 

II. PART 2: RGB-D POINT CLOUD REGISTRATION 
In this section, we aim to register a set of RGB-D frames to a 
reference template to recover the rigid geometry of the scene. 
Unlike the sequential video processing in Part 1, the input 
frames here are not assumed to be consecutive or optimally 
ordered. Consequently, we cannot rely on simple frame-toframe 
chaining. Instead, we must dynamically determine the 
processing sequence by sorting frames based on the quality 
of their feature matches with the template or previous frames. 
Once the optimal path is established, the point clouds are registered 
using Orthogonal Procrustes analysis, which provides a 
closed-form solution for determining the optimal rotation and 
translation between 3D correspondences [3], [4].

III. PART 3: APPLICATION -FORM VALIDATION 
Building on the tracking pipeline, we implemented an automated 
form validation system to detect whether specific 
fields (e.g., “Name”, “Surname”) have been filled in a video 
sequence. 

A. Field Definition and Preprocessing 
We manually defined Regions of Interest (ROIs) on the 
template image to specify the zones to be monitored. The 
input video is subsampled (every 5th frame) to reduce redundancy. 
Each processed frame is rectified using the homography 
pipeline established in Part 1, warping the current camera view 
Icurr to the template coordinate system. The first successfully 
rectified frame is cached as the empty reference Iref, which 
serves as the baseline for background subtraction. 

B. Ink Detection Algorithm 
To detect writing while robustly ignoring the user’s hand 
and dynamic shadows, we employ a difference-based edge 
detection pipeline. 

1) Difference and Edge Extraction: We compute the absolute 
difference map D

Motivation: Simple intensity thresholding is sensitive 
to lighting changes from shadows cast by the writing 
hand. Canny edge detection focuses on gradients, isolating 
pen strokes while ignoring the smoother gradients of shadows. 

2) Hand Rejection via Morphology: Distinguishing pen 
strokes from the edges of the hand or arm is difficult as both 
produce edges in the difference image. We apply morphological

Motivation: Writing strokes are thin and sparse, whereas 
the hand is a large, solid object. The morphological closing

IV. EXPERIMENTAL SETUP AND EVALUATION 
For Part 1, we evaluate the homography estimation pipeline 
using a single template and three RGB sequences (10 frames) 
of increasing difficulty: a fully visible planar case, a planar 
sequence with temporary occlusions, and a sequence with 
out-of-plane motion violating the homography assumption. 
Evaluation is based on qualitative rectification consistency and 
tracking statistics extracted from execution logs, including the 
proportion of frames tracked via direct matching, chaining, or 
identity fallback, as well as typical RANSAC inlier counts. 

For Part 2, we evaluated our system on four datasets: three 
provided by the instructor and one sourced from public repositories 
to validate generalization. We assessed 3D tracking 
performance using frame-to-frame transformation consistency 
and visual inspection of reconstructed point clouds from the 
Google Drive videos.

By studying the videos on the drive, we observed that our 
application performs significantly worse on one dataset compared 
to the others, specifically the airplane safety sheet. 
Empirical testing revealed that the template exhibits poor 
overlap with most frames, producing few matches of low 
quality. As a result, the anchor frame introduce substantial 
error, which propagates through the entire sequence when 
composing transformations. 

Future work should focus on improving robustness in cases 
where the template yields few matches. For this dataset, 
incorporating a plane-fitting algorithm could help mitigate 
these issues and enhance overall performance. 

Once a globally consistent point cloud is reconstructed, the 
resulting geometry provides a foundation for higher-level 
perception tasks. Deep networks that operate directly on point 
clouds can leverage the reconstructed scene without relying 
depth sensors. PointNet was the first to show that such 
networks could perform object classification and segmentation 
directly on point clouds. This demonstrates how dense, registered 
geometry supports downstream 3D vision applications 
beyond the registration step itself [7]. Thus, the proposed 
pipeline functions not only as an alignment mechanism but 
also as a core pillar for learning-based 3D vision. 

C. Part 3 

The morphological approach successfully detects ink in most 
cases. However, a critical limitation emerges: when the hand 
passes over a field and then leaves, the system cannot definitively 
distinguish between pen strokes and hand edges in the 
difference image. This can lead to false positives, where a 
field is marked as filled even though only the hand crossed it 
without writing. 

Potential improvement: Deep learning-based hand detection 
(e.g., using MediaPipe or YOLO-based hand detectors) could 
mitigate this issue by explicitly segmenting and masking hand 
regions before ink detection. By removing hand pixels from 
the edge map before contour analysis, the system could ensure 
that only genuine pen strokes contribute to field validation,

significantly reducing false positives while maintaining robustness

VI. CONCLUSION 
This report presented a pipeline for document tracking and 
rectification across RGB and RGB-D modalities. Part 1 
demonstrated 2D homography estimation using SIFT features, 
RANSAC outlier rejection, and keyframe-based chaining, 
producing perspective-corrected views despite occlusions 
and viewpoint changes. Part 2 extended this to 3D using 
depth data and Procrustes analysis, with anchor selection and 
greedy frame ordering to handle large viewpoint variations. 
Both systems use parameter tuning and multi-pass tracking 
strategies to handle noise and occlusions.
